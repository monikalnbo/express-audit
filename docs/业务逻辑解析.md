# 业务逻辑解析文档

> 本文档对代码进行逐行级解析, 并将实现与原始需求逐条对照。
> 原始需求:
> 1. 导入两份 Excel 表格
> 2. 通过一样的快递单号比对两边的东西是否一致
> 3. 单项的快递单号(只在一方出现)视为异常
> 4. 重量模糊比对: 一边是具体重量, 一边是区间重量
> 5. 异常的对不上的都要标注以及提取出来

---

## 一、需求拆解为可执行规则

| 编号 | 需求 | 拆解后的判定规则 |
|---|---|---|
| R1 | 导入两份 Excel | 读 A 方(具体重量)、B 方(区间重量)两个文件的第一个工作表 |
| R2 | 按单号匹配 | 对 A/B 双方单号做集合运算: 交集=待比对, 差集=单边异常 |
| R3 | 单边单号=异常 | 仅 A 有 → "异常-B方缺单"; 仅 B 有 → "异常-A方缺单" |
| R4 | 重量模糊比对 | 把 B 方区间文本解析成 [下限, 上限], 判断: 下限-容差 ≤ A方重量 ≤ 上限+容差 |
| R5 | 标注+提取 | 全量明细表 + 异常提取表 + A/B 方数据副本中异常行标红并写备注 |

## 二、compare_engine.py 逐段解析

### 2.1 单位换算表 (L15-16)

```python
UNIT_FACTOR = {"mg": 0.000001, "g": 0.001, "克": 0.001, "kg": 1.0,
               "公斤": 1.0, "千克": 1.0, "吨": 1000.0, "t": 1000.0,
               "lb": 0.453592, "磅": 0.453592}
```

- 业务意义: 统一度量衡。A 方"500克"与 B 方"0.4-0.6kg"必须换算到同一单位才能比较。
- 设计决策: **一切归一到 kg**。所有解析函数输出均为 kg 数值。
- 注意: "公斤/千克/kg"系数都是 1.0, 但三者都必须显式列出——否则"千克"会落入"克"(0.001)的判断, 造成千倍误差(此 bug 已修复)。

### 2.2 parse_weight_value — A 方具体重量解析 (L18-33)

逐行逻辑:

```
L19-20  空值防御: None 或 pandas 的 NaN → 返回 None (表示"无法解析")
L21     统一转小写、去空格 → 兼容 "1.5 KG"、"1.5kg"、"1.5 kg"
L23     正则 ([\d.]+)\s*(单位)? 提取数字和单位
        - 单位是可选组: "1.5" 无单位时按 kg 处理(L30 or "kg")
        - 单位枚举按长短排序(mg 在 g 前), 防止误匹配
L24-28  float() 转换失败(如 "1..5") → None, 不抛异常
L29-31  数字 × 单位系数 = kg 数值
```

需求映射: 服务于 R4 的"A 方一侧"。业务上快递重量几乎总在单号旁附带, 所以正则用 search 而非 fullmatch——允许"重量：2.3kg"这类带前缀的单元格也能提取。

### 2.3 parse_weight_range — B 方区间解析 (L35-71)

这是模糊比对的核心。四种区间形态, 按优先级依次尝试:

```
形态1 (L43-49): 区间式   "1-2" / "0.5~1.5公斤" / "1至2kg"
        正则 ^(\d+)[~\-至](\d+) 锚定开头, 提取上下限
        min/max 归一 → 容错"2-1"这种手写颠倒
        单位由 _unit_of() 从整串识别, 乘在两侧

形态2 (L51-55): 开口向下 "小于3" / "<5" / "不超过2.5"
        解析为 (0, v) —— 重量非负, 下限天然是 0

形态3 (L57-61): 开口向上 "大于1" / ">=" / "3以上"
        解析为 (v, +inf)

形态4 (L63-66): 纯数字    "2.5" 或 "2.5kg"
        业务含义: 有些网点把"约重"填成一个数
        解析为 (v, v) 即零宽区间 —— 数值完全相等才算一致
```

设计决策与理由:
- 顺序很重要: 必须先试区间式, 否则 "1-2" 会被形态2的正则部分命中。
- `～`(全角)、`—`、`–` 在 L41 统一替换为半角, 因为中文录入习惯五花八门。
- 未匹配任何形态 → None → weight_match 判为"B方区间无法解析"并进入异常表。**这本身是一个审查发现**: 说明 B 方有脏数据, 不能静默跳过。

### 2.4 _unit_of — 区间字符串的单位识别 (L73-82)

```
L74  公斤/千克/kg → 1.0   (必须先判, 否则"千克"会被 L75 的"克"劫持)
L75  克 → 0.001
L76-78  mg/lb/吨/磅 子串匹配
L79-80  "2t" 这种纯字母吨 → 1000
L81-82  都没有 → 默认 kg
```

需求映射: R4。默认 kg 是因为快递场景 90% 的区间不带单位("1-2")。

### 2.5 weight_match — 核心判定 (L85-98)

```python
if lo - tolerance <= exact_kg <= hi + tolerance:  → 正常
else:                                             → 重量不符
```

- 这一行就是需求 R4 的全部数学表达: **闭区间 + 容差**。
- 边界决策: 区间端点算一致(≤), 即 2.0kg 落在 "1-2" 内算正常。容差默认 0, 用户可设 ±50g 等。
- 说明文案同时用于报告展示和日志, 如 `9.900kg ∉ [2, 4]`, 让审查人员一眼看到为什么判不一致。

### 2.6 compare — 主比对流程 (L100-150)

```
L104-105  按 R1 读入两份 Excel; dtype={key:str} 强制单号列读为字符串
          → 防止 "07551234" 被 pandas 读成数字丢失前导零(快递单常见!)
L107-111  单号清洗: notna 过滤 + strip 去空格 + 丢弃空串
          → 防止空单元格变成单号 "nan" 参与匹配或导致排序崩溃(已修复的 bug)
L113-116  集合运算: only_a = A-B (R3 左半), only_b = B-A (R3 右半),
          common = 交集 (进入 R4 比对)
L120-137  交集内逐对比较:
          同一单号双方各有多条记录时做笛卡尔积 —— 任一组合重量一致即记"正常",
          但所有组合都会写入明细表, 审查时可追溯
L139-149  单边单号: 取该侧首行数据生成异常记录, 说明字段写明方向
          ("仅在A方存在" = B方漏了这一单, 反之亦然)
L150      返回 (明细DataFrame, A原df, B原df)
```

### 2.7 export_report — 报告生成 (L178-217)

对应需求 R5 的三个产物:

```
Sheet1 比对明细  = 全量结果(含正常的), 供整体浏览
Sheet2 异常提取  = results 中 审查结果 != "正常" 的子集 ← R5"提取出来"
Sheet3/4 A/B方标注 = 原表数据的完整副本 + 两列内部标记:
    _异常: 该行行号是否出现在异常记录的 _row_a/_row_b 集合中
    _说明: "[异常类型] 原因" 文案
_annotate_sheet (L155-176) 写出时:
    - 内部列(下划线开头)不写入文件
    - 异常行的 单号列+重量列 标红加粗 ← R5"标注"
    - 行尾追加"审查备注"列写明原因
```

行号约定: `_row = df.index + 2`, 因为 DataFrame 从 0 计数而 Excel 第 1 行是表头。

### 4.1 深入业务推演后补充的规则(第二阶段)

仅实现 R1-R5 不够。站在真实对账业务的审查员视角推演后发现以下场景,
已全部补充实现:

| 编号 | 场景 | 风险 | 补充规则 |
|---|---|---|---|
| B1 | 同一单号在A方录入2次(一单多包裹) | 数量不匹配无感知 | 明细增加"A方记录数/B方记录数"两列 |
| B2 | 同侧重复录入同一单号 | 可能是录错, 是重要对账线索 | 生成"提示-X方单号重复"记录并进入异常提取表 |
| B3 | 全角字符(１－２、２．５ｋｇ) | 中文Excel手输常见, 原解析直接失败 | 解析前做 NFKC 归一化转半角 |
| B4 | 缺单单号在来源侧有多条 | 只标第一条, 其余漏标 | export_report 按"缺单单号集合"标注所有行 |

B2 的判定口径: 重复本身不判为"异常", 而是生成独立类别的"提示",
因为\"一单多包裹\"与\"重复录入\"在数据上无法区分, 必须由人工确认;
但提示会进入异常提取表, 保证不被淹没。

## 五、边界情况决策清单(已明确的行为)

1. **同一单号多条记录**: 笛卡尔积逐对比对; 明细含双方记录数; 同侧重复额外生成提示。
2. **区间端点**: 闭区间, 2.0 ∈ "1-2" 算一致。
3. **无法解析的区间文本**: 判"重量不符"并注明原因——脏数据本身就是审查对象。
4. **空单号**: 直接忽略, 不产生异常记录。
5. **无单位数字**: 按 kg 处理(快递行业惯例)。
6. **前导零单号**: dtype=str 保证不丢。
7. **全角字符**: NFKC 归一化后正常解析。
8. **缺单单号多条**: 所有出现行均标红, 说明注明总条数。
